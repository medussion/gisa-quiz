# 문제 추가 가이드

문제를 넣는 방법은 두 가지다. **둘 다 같은 검증 규칙을 거치고 같은 JSON 파일에 쌓인다.**

| 방법 | 언제 |
| --- | --- |
| 웹 화면 (`/questions/new`, 문제 목록의 `+ 문제 추가`) | 한두 문제를 바로 넣을 때. 미리보기·중복 확인이 된다 |
| JSON 파일 + CLI | 한 회차를 통째로 넣을 때 |

이미 있는 문제는 **문제 상세 화면의 `수정` 버튼**(또는 풀이 화면의 `문제 수정`)으로 고친다.
자세한 내용은 아래 [0-1. 웹에서 고치기](#0-1-웹에서-고치기).

## 0. 웹에서 추가하기

문제 목록 화면 오른쪽 위 **`+ 문제 추가`** 버튼을 누른다.

- 출처 유형을 고르면 필요한 칸이 따라 나온다 (기출을 고르면 연도·회차·출처 URL 칸이 생긴다)
- `id` 는 비워두면 자동으로 만들어진다 — 기출은 `2024-2-001`, 그 외는 `user-0001`
- `힌트` 는 비워도 된다. 비우면 정답 글자 수·첫 글자로 자동 생성된다
- 정답을 여러 줄 쓰면 빈칸이 여러 개인 문제로 채점된다 (아래 3장 참고)
- `푸는 화면으로 미리보기` 로 실제로 어떻게 보일지 확인할 수 있다
- 저장하면 비슷한 문제가 이미 있는지 알려준다. 막지는 않으니 직접 판단한다
- `저장하고 계속` 은 출처·영역 같은 메타 정보를 남긴 채 본문만 비운다. 한 회차를 연달아 넣을 때 쓴다

저장한 문제는 DB와 **`data/normalized/user-added.json`** 에 함께 기록된다.
그래서 `CONFIRM=yes npm run db:reset` 으로 DB를 지워도 `npm run questions:import` 하면 되살아나고,
파일을 직접 열어 고칠 수도 있다. 고친 뒤에는 `npm run questions:import` 를 다시 실행한다.

## 0-1. 웹에서 고치기

문제 상세 화면 오른쪽 위 **`수정`** 버튼, 또는 풀이 화면에서 채점 결과 아래 **`문제 수정`**.
정답이 틀렸거나 오타를 봤을 때 그 자리에서 고칠 수 있다.

- **id는 바꿀 수 없다.** id가 풀이 이력·오답노트·복습 주기를 묶고 있어서, 바꾸면 지금까지 푼 기록이 끊긴다.
  대신 고쳐도 풀이 이력·북마크·메모는 그대로 남는다.
- 저장하면 DB와 **그 문제가 원래 들어 있던 JSON 파일**을 함께 고친다.
  `questions.json` 의 문제를 고치면 `questions.json` 이 바뀌므로, 다음 `questions:import` 때 되돌아가지 않는다.
- **`출제에서 제외`** 체크박스로 문제를 지우지 않고 출제 대상에서만 뺄 수 있다.
  제외한 문제는 문제 목록의 **`출제 제외`** 칩으로 다시 찾아서 되돌린다.
- 정말로 지우려면 JSON 파일에서 해당 항목을 빼고 `CONFIRM=yes npm run db:reset && npm run setup` 을 한다.
  (풀이 이력까지 전부 사라지므로 보통은 `출제에서 제외` 로 충분하다)

## 1. 어디에 넣나

`data/normalized/` 아래 `*.json` 파일이면 모두 읽는다. 파일을 나눠도 된다.

```
data/normalized/
├── questions.json      ← 기본 제공 샘플 (기출 아님)
├── user-added.json     ← 웹에서 추가한 문제 (자동 생성)
├── 2024.json           ← 직접 만든 기출 파일
└── 2025.json
```

각 파일의 최상위는 **배열**이다. 스키마는 [`data/question.schema.json`](../data/question.schema.json).
VS Code라면 파일 맨 위에 다음을 넣으면 자동완성이 된다.

```jsonc
// .vscode/settings.json
{
  "json.schemas": [
    { "fileMatch": ["data/normalized/*.json"], "url": "./data/question.schema.json" }
  ]
}
```

## 2. 최소 형태

```json
[
  {
    "id": "2024-2-013",
    "sourceType": "past_exam",
    "sourceLabel": "2024년 2회 실기 복원",
    "sourceUrls": ["https://example.com/복원글"],
    "year": 2024,
    "round": 2,
    "category": "sql",
    "questionType": "sql",
    "question": "학생(STUDENT) 테이블에서 이름(NAME)을 검색하는 SQL문을 작성하시오.",
    "answer": ["SELECT NAME FROM STUDENT;"],
    "explanation": "기본 SELECT문이다.",
    "verificationStatus": "single_source"
  }
]
```

필수는 `id`, `sourceType`, `category`, `questionType`, `question`, `answer` 여섯 개다.
나머지는 기본값이 채워진다.

## 3. 필드별 주의점

### `id`

전역 고유해야 한다. 기출은 `연도-회차-번호` 를 권장한다 (`2024-2-013`).
**같은 id로 다시 import 하면 문제 내용은 덮어쓰고, 풀이 이력·북마크·메모는 그대로 유지된다.**
문제 오타를 고칠 때 id를 바꾸지 말 것. id를 바꾸면 이력이 끊긴다.

### `sourceType` — 실제 기출만 `past_exam`

| 값 | 쓸 때 |
| --- | --- |
| `past_exam` | 실제 시행된 기출 / 복원 문제 |
| `generated` | AI가 기출을 변형해 만든 문제. `basedOn` 에 원본 id를 넣는다 |
| `sample` | 앱 확인용 자체 제작 문제 |
| `user` | 교재·노트 등 개인 자료에서 옮긴 문제 |

**확실하지 않은 문제를 `past_exam` 으로 표시하지 않는다.** 출처가 없으면 `user` 나 `sample` 이 맞다.

### `verificationStatus`

| 값 | 뜻 |
| --- | --- |
| `unverified` | 정답을 아직 확인하지 못함 (기본값) |
| `single_source` | 출처가 하나뿐 |
| `cross_checked` | 서로 다른 2곳 이상에서 같은 정답 확인 |
| `verified` | 확실함 |
| `rejected` | 문제/정답이 틀린 것으로 판명. 출제에서 제외된다 |

정답이 헷갈리면 지어내지 말고 `unverified` 로 두면 된다. 화면에 미검증 경고가 뜬다.
`npm run questions:unverified` 로 정리 대상을 뽑을 수 있다.

### `category`

Q-Net 실기 출제기준 12개 주요항목을 그대로 쓴다.

| id | 주요항목 |
| --- | --- |
| `requirements` | 요구사항 확인 |
| `data_io` | 데이터 입출력 구현 |
| `integration` | 통합 구현 |
| `server_programming` | 서버 프로그램 구현 |
| `interface` | 인터페이스 구현 |
| `ui_design` | 화면 설계 |
| `testing` | 애플리케이션 테스트 관리 |
| `sql` | SQL 응용 |
| `security` | 소프트웨어 개발 보안 구축 |
| `programming_language` | 프로그래밍 언어 활용 |
| `app_sw_basics` | 응용 SW 기초 기술 활용 |
| `packaging` | 제품 소프트웨어 패키징 |
| `etc` | 위에 안 맞을 때 |

목록을 바꾸려면 `src/lib/constants.ts` 의 `CATEGORIES` 만 고치면 된다. DB 마이그레이션은 필요 없다.

### `questionType`

| id | 입력 UI |
| --- | --- |
| `short_answer` | 한 줄 입력 |
| `term` | 한 줄 입력 |
| `code_output` | 여러 줄 입력 (고정폭) |
| `sql` | 여러 줄 입력 + 수동 보정 버튼 |
| `descriptive` | 여러 줄 입력 + 수동 보정 버튼 (설명을 문장으로 쓰는 문제) |
| `multiple_choice` | 한 줄 입력 (`choices` 필수, `answer` 는 보기 번호 문자열) |

### `answer` / `acceptedAnswers`

`answer` 가 1개면 단일 정답, 2개 이상이면 **빈칸이 여러 개**라는 뜻이다.
빈칸이 여러 개면 사용자는 줄바꿈이나 쉼표로 구분해 입력하고, 맞힌 개수만큼 부분 점수가 나온다.

```json
{
  "question": "(1) FIFO 구조와 (2) LIFO 구조의 자료구조 이름을 쓰시오.",
  "answer": ["큐", "스택"],
  "acceptedAnswers": ["Queue", "Stack"],
  "orderSensitive": true
}
```

- `orderSensitive: true` — 순서까지 맞아야 한다 (기본값은 `false`)
- `acceptedAnswers` 는 **모든 빈칸에 공통으로 허용**되는 표기 목록이다. 영문 표기, 축약형, 띄어쓰기 변형을 넣어 둔다.
- `caseSensitive: true` — 대소문자를 구분한다. 문자열 출력 결과 문제에만 쓴다.

### `code` / `codeLang`

코드, SQL, 표 등 본문에 붙는 블록은 `question` 이 아니라 `code` 에 넣는다. 고정폭 블록으로 따로 렌더링된다.
`codeLang` 은 `c`, `java`, `python`, `sql`, `text` 등 메모용이다.

```json
{
  "questionType": "code_output",
  "codeLang": "python",
  "code": "a = [1, 2, 3]\nprint(sum(a))",
  "question": "다음 Python 프로그램의 실행 결과를 쓰시오.",
  "answer": ["6"]
}
```

### `hint`

풀이 화면의 `힌트 보기` 에 쓰인다. **비워두면 정답의 모양으로 자동 생성**되므로 필수는 아니다.

| `hint` | 화면에 나오는 것 |
| --- | --- |
| 없음 | `분야: 트랜잭션` + `한글 3글자, 「원」(으)로 시작합니다.` |
| `"ACID의 첫 글자에 해당합니다."` | 적은 문장 그대로 |

자동 생성 규칙 — 1글자 정답은 첫 글자를 공개하지 않고, 숫자는 자릿수만, SQL은 첫 키워드만,
빈칸이 여러 개면 칸마다 따로 알려준다. 정답 문자열 자체는 브라우저로 내려가지 않는다.

**힌트에 정답을 그대로 쓰지 않는다.** "어디를 보면 되는지"만 짚어준다.

```json
{
  "question": "제어 흐름 그래프의 노드가 10개, 간선이 13개일 때 순환 복잡도는?",
  "answer": ["5"],
  "hint": "V(G) = 간선 - 노드 + 2 공식을 씁니다."
}
```

### `difficulty`

1~5. 출제 우선순위에 약하게 반영된다. 모르면 3으로 둔다.

## 4. 넣는 절차

```bash
npm run questions:validate     # 1. 검사 (오류가 있으면 종료 코드 1)
npm run questions:import       # 2. DB 반영 (검사 통과분만)
npm run questions:duplicates   # 3. 중복 후보 확인 (선택)
npm run questions:unverified   # 4. 검증 필요 목록 (선택)
```

- 특정 파일만 다루려면 경로를 붙인다: `npm run questions:validate data/normalized/2024.json`
- **오류가 있는 문제는 import 되지 않고** `data/rejected/rejected-*.json` 에 이유와 함께 기록된다.
- 경고(warning)는 import를 막지 않는다. `past_exam` 인데 출처 URL이 없거나 해설이 비었을 때 뜬다.
- 중복 탐지는 정규화 본문 + 유사도로 **후보만** 뽑는다. 자동 병합은 하지 않으니 직접 확인하고 합친다.
  임계값을 바꾸려면: `npm run questions:duplicates -- data/normalized/2024.json 0.8`

import 후 앱을 새로고침하면 바로 반영된다. 서버를 다시 띄울 필요는 없다.

## 5. AI 변형 문제를 만들 때

단순히 말만 바꾸지 말고, **개념을 다시 풀어야 답이 나오도록** 바꾼다.

- SQL: 테이블 데이터 · 조건 · 집계 함수를 바꾼다
- 코드: 변수 값 · 반복 범위 · 연산자를 바꾼다

만든 뒤 정답을 **직접 다시 계산해서 검증**한다. 검증할 수 없으면 DB에 넣지 않는다.

```json
{
  "id": "gen-2024-2-013-a",
  "sourceType": "generated",
  "basedOn": "2024-2-013",
  "verificationStatus": "unverified"
}
```

시험 직전에는 `/study?mode=past_only` 로 AI 문제를 완전히 빼고 풀 수 있다.

## 5-1. 공개 기출 자동 수집

`npm run collect` 로 공개 문제은행에서 기출을 모은다. 단계는
`collect:fetch`(원문 저장) → `collect:parse`(정규화) → `questions:validate` → `questions:import` 이고,
각 단계는 다시 실행해도 된다.

- 받은 원문은 `data/raw/<연도>/newbt-<연도>-<회차>.html`, 출처 URL과 받은 시각은 같은 이름의 `.source.json`
- 파싱 결과는 `data/normalized/past-<연도>.json`
- 본문이 글자가 아니라 그림으로 올라온 문항은 이미지를 `public/question-images/` 로 꺼내 `image` 필드에 넣는다
- 영역 분류는 `scripts/collect/classify.ts` 의 규칙 기반이다. 틀린 게 보이면 규칙을 고치고 다시 파싱하거나,
  웹의 `수정` 화면에서 그 문항만 바꾸면 된다
- 수집한 문항은 기본이 `single_source` 다. `npm run collect:crosscheck` 로 검증 상태를 올린다

### 해설 파일

수집한 기출에는 출처에 해설이 없다. 그래서 해설은 [`data/explanations.json`](../data/explanations.json) 에
`{ "문항id": "해설" }` 형태로 따로 모아 두고, `collect:parse` 가 파싱 마지막에 덮어씌운다.

```bash
# 해설 묶음 파일을 합칠 때
npx tsx scripts/collect/merge-explanations.ts batch.json
```

이미 해설이 있는 문항은 건드리지 않고 비어 있는 것만 채운다.

### 보정 파일

원문을 다시 파싱하면 `data/normalized/past-*.json` 은 통째로 다시 만들어진다.
그래서 손으로 고친 내용은 [`data/corrections.json`](../data/corrections.json) 에 적는다.
`collect:parse` 가 마지막에 이 파일을 덮어씌우므로 몇 번을 다시 파싱해도 살아남는다.

```json
{
  "corrections": [
    {
      "id": "2023-3-012",
      "reason": "왜 고쳤는지 반드시 적는다. 근거가 없으면 무시된다.",
      "source": "https://근거-링크",
      "patch": { "answer": ["NAT(Network Address Translation)"] }
    }
  ]
}
```

웹의 `수정` 화면으로 고친 것은 DB와 원본 JSON에 바로 반영되지만,
**수집한 기출을 고쳤다면 다시 파싱할 때를 대비해 보정 파일에도 적어두는 편이 안전하다.**

## 6. 수집할 때 지키는 것

- 공개 접근 가능한 자료만 본다. 로그인/유료벽을 우회하지 않는다.
- 사이트의 이용 정책과 접근 제한을 존중한다.
- 상용 교재를 통째로 복제하거나 재배포하지 않는다. 개인 학습 목적으로만 쓴다.
- 출처 URL과 라벨을 반드시 `sourceUrls` / `sourceLabel` 에 남긴다.
- 같은 문제·정답은 가능하면 두 곳 이상에서 교차 확인하고 `verificationCount` 를 올린다.
  단일 블로그의 답을 무조건 믿지 않는다.
- **출처가 불확실한 정보를 사실처럼 꾸미지 않는다.**
